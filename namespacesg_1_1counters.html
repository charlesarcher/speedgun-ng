SPEEDGUN_NG_EXPORT auto sg::counters::coreWideCoverage() -> std::optional< CoreCoverage >
#include <speedgun-ng/counters_metrics.hpp>

Answers how much of a core the cpus of this process cover, and answers nothing where the host states no sibling lists (specs/042-topdown FR-042, FR-043, spec D-6).

The answer comes from the cpu set this process holds and the sibling list of every cpu that set holds. That is the one reader the #core_wide row of a table reads through, so the query and a folded row answer one thing and a caller that states the scope of a run asks here.

Nothing stands settled before the first call. One value then stands for the life of the process, because a table resolves once per directory and the conditional over the constant folds when it resolves, so a second call answers what the first answered and a caller carries no reader of its own (FR-042, spec D-6). A settled value never moves inside one process. The value names a whole core with every sibling of it, or one thread of a core, and states no slot width: the width is a literal of the table. An absent answer keeps the standing refusal of #core_wide, so a row that needs the fact stays refused (FR-043).

Precondition

none

Postcondition

SPEEDGUN_NG_EXPORT auto sg::counters::objectLimitSource(std::string_view objectPath) noexcept -> LimitSource noexcept
#include <speedgun-ng/counters_system.hpp>

The source of the limit programmableCounters() answers for objectPath (FR-040a, FR-043, FR-053, D-3, D-3a).

A provider records the source beside the limit it publishes, and this accessor answers the pair, so a run can say which finder answered the count it planned with (FR-050, FR-051). objectPath is the catalog address: the same text Object::programmableCounters() reads. A path no provider recorded answers NONE, and so does a path whose published limit stands absent.

The accessor states no claim about the catalog of the process. It reads one record beside the tree, resolves no path, and opens nothing.

Precondition

none

Postcondition

the answer is NONE exactly where Object::programmableCounters() answers no value for that path (FR-040a)

a recorded path answers the source that filled its limit, and the answer stands for the life of the process once the catalog is open (FR-043, FR-009)

SPEEDGUN_NG_EXPORT auto sg::counters::cpuIdentity() -> CpuIdentity
#include <speedgun-ng/counters_topdown.hpp>

The identity of the cpu this process runs on.

The four fields the library already reads come from its own reader, and the two fields no reader answers stand absent, so a caller cannot tell a hybrid part or an Arm part from a production identity. The reader caches, so the call runs its reader once per process at the first call and reads nothing at a later one.

Precondition

none

Postcondition

The first four fields equal the library's own cpu reader's answer, coreType is empty and midr is unset: no reader for either exists in this feature (FR-003, spec D-13).

SPEEDGUN_NG_EXPORT auto sg::counters::topdownTable(const CpuIdentity& identity) -> TopdownTable
#include <speedgun-ng/counters_topdown.hpp>

The table of one identity: the directory the vendored mapping file gives it, beside the rows of that directory.

The mapping file is matched row by row and the first row that hits names the directory, so the identity's vendor, family, model and stepping decide the answer between them. A core type and an MIDR join no key, so neither moves a selection: no mapping-file row reads either (spec D-13).

The call reads no counter, opens no event, reads no clock and calls no cpu reader of its own, so the same identity answers the same table in the same process (FR-002, FR-009).

Precondition

none

Postcondition

An empty source.directory names an identity the mapping file matched no row for, and rows then stands empty. Every row of the selected directory answers a verdict, published or refused, in the sorted file order the embedder emits (FR-001, FR-016).

SPEEDGUN_NG_EXPORT auto sg::counters::topdownEventGroups(const CpuIdentity& identity) -> std::vector< TopdownEventGroup >
#include <speedgun-ng/counters_topdown.hpp>

specs/046-hunter-topdown FR-004, FR-008, D-16: the grouping listing of one identity: the pairs the directory that identity selects holds.

The call reads the embedded table of the selected directory, and that table is build-time data the loader holds once per directory. No vendored path opens at run time and no host probe is made (D-16).

Postcondition

An identity that selects no directory answers an empty listing (D-16). The call reads no counter, opens no event, reads no clock, opens no path, and reads no MIDR field beyond the directory the identity selects (D-13).

The tree one selection asks for, built from the rows of one table (specs/042-topdown FR-002, FR-008 to FR-016, FR-020; data-model E-08).

The answer follows from options.identity and from one table: the planted options.table where one stands, and the table of the identity where none stands. The call reads no counter, opens no event, reads no clock and calls no cpu reader of its own, so two calls over one identity and one table answer one tree (FR-002, FR-009). The rows reach the call as the verdicts the metric layer answers, and a directory resolves once, so the pass that builds a tree reads those verdicts as data.

A row reaches a node when its group text carries a level token of TopdownL1 to TopdownL6, PipelineL1 or PipelineL2, when that level stands at or above the depth the answer states, and when its parent already stands in the tree (FR-013, FR-014). A level-1 row roots a node and names no parent. A deeper row names its parent with the _group token of its own group text: Intel spells that token tma_<name>_group and AMD spells it <name>_group, and the stem of either names another row of the table. A row whose token stems to no row reaches no node, and no part of this feature invents a parent for it (FR-013). The rows are walked level by level, so every parent names an earlier element of nodes: a caller folds a parent before it folds the children of that parent. A node's level stands one below its parent's level. Measured over the vendored tables: 98 group tokens of arch/x86/skylakex/ and 111 of arch/x86/sapphirerapids/ stem to a row of the same table, and every one of them names a row exactly one level above.

depth is the asked level clamped to the deepest level token the table holds, so a table of level-1 rows answers level 1 whatever the ask (FR-008, FR-020). A row the host refuses stands in refused with the metric layer's kind and reason beside its own name, its parent and its level, and it builds no node (FR-016, FR-031). A node carries the spine of its row and the address of every leaf that spine reads, which is what a run groups its passes on (FR-010, FR-021).

An identity no table serves, a table that names no directory, a directory that publishes the two core scopes of a hybrid part, an MIDR, and a directory that holds no row of any top-down group answer one TopdownUnsupported in place of a tree, in that order. Each carries a kind and the fields its rule states, so it names the vendor, the identity and the directory or sentence its rule read, and none of them reaches a node, an event or a counter (FR-004 to FR-007). The scope rule reads the Unit text of the directory's own event rows, so the rows carry the two-scope fact and no list of directory names stands in this feature (FR-006). message() owns the one line a caller prints for any of the five (FR-040, spec D-14).

Precondition

options.level stands in 1 to 6, and SG_REQUIRE enforces that.

Postcondition

The answer is pure over the identity and the rows: no counter read, no event open, no clock read and no CPUID read stand behind it (FR-002, FR-009). depth is the asked level clamped to the deepest level the table holds (FR-008, FR-020), and no node stands that a row of the table does not state (FR-013). A refusal carries the kind its rule states, the vendor and identity text of the identity it read, and the directory or sentence its rule read (FR-004 to FR-007, FR-040).

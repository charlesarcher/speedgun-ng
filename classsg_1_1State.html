sg::State class
#include <speedgun-ng/benchmark.hpp>

The object the harness hands the benchmark function (E-03).

Contents

  • Reference
    • Public types
    • Public static functions
    • Public functions

The function runs its setup, the timed loop as for (auto _ : state), and its teardown; setup and teardown sit outside the loop, in the untimed region (FR-004, FR-005). The sampling window opens in begin() and closes when the loop runs out, so the window covers the loop and not the setup or the teardown (FR-017). The loop cursor counts down from the iteration count of the current run, so it cannot pass that count by construction, and the loop reads no interrupt flag: the runner reads that flag after a run completes (R-06).

Cursor sg::State::begin() noexcept

The cursor at the first iteration of the timed loop.

The skip flag is read here, once for the loop. A skip requested before the loop leaves the loop with no pass at all and takes no sample. Otherwise this is where the run's sampling window opens, before the first pass of the loop and after the setup the function already ran (FR-005, FR-017).

Precondition

this state belongs to a run: a callback state opens no sampling window, so opening one here is a precondition violation (R-05)

Postcondition

the returned cursor names iteration zero of this run with the entry sample taken, or an empty cursor when the function already requested a skip

void sg::State::skipWithError(std::string_view reason) noexcept

Skip the benchmark with an error reason (FR-031).

A skip inside the loop closes the sampling window at once, so the measured window stops where the function stops, the way the upstream timer stops its clock (FR-017).

Precondition

this state belongs to a run: a skip in a callback state is a precondition violation (R-05)

Postcondition

the reason is recorded, the function leaves the timed loop with break or return, and no statistics print for this benchmark

void sg::State::setIterationTime(std::int64_t nanoseconds)

Add one iteration time to the manual accumulator (FR-007).

A manual benchmark supplies its own time: this call takes one nanosecond count per iteration and the harness records the sum of the accepted values by summation alone, with no clock behind it. The real column of the run shows that sum divided by the iteration count (FR-006, FR-007, D-05). The call stands in the benchmark body, inside the timed loop or outside it, and the run state owns the accumulator.

Precondition

this state belongs to a run: a callback state owns no run to accumulate for, so accepting a value there is a precondition violation (R-05, D-15)

the count is at least zero: a duration has no negative nanoseconds, and a negative value is accepted nowhere without naming its caller (FR-007)

Postcondition

the manual accumulator carries the sum of every accepted value, this one included (FR-007)

void sg::State::setCounter(std::string_view name, const Counter& counter)

Set the value, flags, and base of one named counter (FR-001, FR-002).

The call stands in the timed loop or in a body callback state of the run (FR-001). A name the run has not opened takes the flags and the base of this call and keeps them for the run's life, and a later call for that name writes the value alone (FR-001, FR-008). The runner applies the flags once per repetition after the loop, and the report prints one column per name in the order the names opened (FR-003, FR-006). The name copies into fixed storage, so opening a name allocates nothing (FR-007).

A second call for a used name with another flags value or another base fails the run with a reason naming that name: the reason is a runtime text, and an SG_REQUIRE message is a literal, so the state records the failure and the run ends with it (FR-008).

Precondition

name holds at most kMaxCounterNameBytes minus one bytes, a free slot stands when name is new, and a used name carries the flags and the base it opened with (FR-001, FR-002, FR-008)

Postcondition

the run carries name with the value of the argument, and a used name keeps the flags and base it opened with (FR-001)

void sg::State::setBytesProcessed(std::int64_t bytes)

Set the byte-throughput column to the count this call passes (FR-009).

The call takes the total bytes the run did, so a body that works a known amount per iteration passes that amount times the iteration count after the loop (FR-009). The call opens bytes_per_second with the RATE flag and the K1024 base, so the printed column is this count divided by the primary time of the row in seconds; the base carries the Ki suffix a rendered value would show and divides nothing further (FR-003, FR-006, FR-009). A later call writes the count alone, as for any used name (FR-001).

Precondition

the run has opened at least one free counter name besides the throughput columns it already opened, as the two throughput setters share the cap of sixteen names (FR-001)

Postcondition

the run carries bytes_per_second with the value of the argument, the RATE flag and the K1024 base (FR-009)

void sg::State::setLabel(std::string_view label)

Set the label of this repetition (FR-011).

The runner copies the string to the row after the loop, and the report prints it as the trailing label=<text> field of that row, present only when the row carries a label (FR-011, the clarification of 2026-10-14). The last call of a repetition wins, and the aggregate row takes the label only when every repetition shares it (FR-012, D-04).

Precondition

label holds no newline character: the report prints one line per row, so a label that breaks the line is a violation at the call (spec Edge Cases, FR-011)

Postcondition

this repetition carries label in place of any label an earlier call of it set (FR-011, D-04)

void sg::State::pauseTiming()

Stop the timed window from this point (FR-009).

The call stands in the benchmark body. It takes one sampling action, the same action the endpoint pair takes, and opens one pause interval that resumeTiming closes (FR-009). The runner folds every closed interval and subtracts it from each column of the row (FR-010). When the run's recorder holds no room for the pair, the pair stands on the fold path instead: the run's two-point slot takes the points and the commit folds them into the row's running totals, so no closed pair is lost and no fixed allowance bounds the run (FR-025, FR-052, Q-10).

Precondition

this state belongs to a run, its sampling window stands open and unclosed, and no pause stands open on it (FR-011, D-15)

Postcondition

one pause stands open, and one sampling action stands in the run's recorder or in the run's fold slot (FR-009, FR-052)

void sg::State::resumeTiming()

Restart the timed window and record the interval it paused (FR-009).

The call takes the sample that closes the open pause, records the pair of sample ordinals of that interval inside the run's span, or, on the fold path, folds the pair into the row's running totals at this commit, and counts one interval for the run (E-03, FR-018, FR-052).

Precondition

this state belongs to a run and one pause stands open on it (FR-011, D-15)

Postcondition

one further sample stands in the run's span, the ordinal pair of the closed interval stands in the run's pause list, and no pause is open (FR-009, E-03)

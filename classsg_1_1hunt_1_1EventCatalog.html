sg::hunt::EventCatalog class
#include <speedgun-ng/hunt.hpp>

The selection of events a hunt run takes, expanded against the catalog (E-01).

One instance per hunt run. Discovery reads System::local().object("machine"), its children() and Object::counters(), the walk catalog.cpp already performs; no clock and no counter read enter this class (FR-003).

std::expected<void, counters::Error> sg::hunt::EventCatalog::expand(std::string_view selection)

Expands the selection text into the catalog addresses it selects, in catalog order.

The text is what the option carried: all, one glob pattern, or a catalog address list whose entries are separated by commas, newlines or both; the text of an @file arrives as its address lines under the same separator rule. No shape of that text is a precondition, because a text outside the three answers a recoverable error naming the value (FR-004 to FR-006).

Precondition

none

Postcondition

on success addresses() holds the selected catalog addresses in catalog order, deduplicated by address, for all and the pattern in catalog-scan order and for a list in the order of the text; an unknown address, a pattern that matches nothing, an empty address line and a raw event code shaped r[0-9a-fA-F]+ are recoverable errors naming the value (D-10, D-11); no raw code resolves on any host (spec PC-6)

const std::vector<std::string>& sg::hunt::EventCatalog::addresses() const

The deduplicated selection in catalog order (E-01).

std::pair<std::vector<CatalogAddress>, std::vector<SkippedEvent>> sg::hunt::EventCatalog::split(std::uint64_t seed) const

Splits the selection into the columns the plan seats and the entries discovery refused, under the seed shuffle of --hunt-seed (E-01, FR-002, FR-010, FR-014).

Precondition

expand returned no error

Postcondition

the first member holds one entry per address whose Availability is COUNTABLE in the order the seed shuffle of --hunt-seed gave, and the second member holds one SkippedEvent per refused entry carrying that entry's Availability as its kind; no address stands in both members, because the discovery answer decides membership uniquely

bool sg::hunt::EventCatalog::isCoreDevice(std::string_view address) const

True when the device of one address is a core device (E-01, D-1).

Precondition

none

Postcondition

true for the device part cpu, cpu_core and cpu_atom and for a device part that starts with armv8_ (the prefix rule of D-1, new hunt-side code with no library helper); false for every other device, uncore included (D-1)

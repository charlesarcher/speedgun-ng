speedgun-ng

A benchmark framework in the lineage of Google Benchmark, written in C++23 for Linux, the one supported platform. A benchmark is a function over a State object: you write the loop, register the function, and read a report of time per iteration.

What speedgun does

  • Draws every time value and every counter value from the counters library of this project.
  • Attaches hardware counter metrics to a benchmark, printed beside the timing columns of the same run.
  • Guards its public API with design-by-contract checks at the boundaries.

Quick start

Linux, a C++23 compiler, and CMake 3.20 or newer. Configure, build, and install the library:

cmake -S . -B build -D CMAKE_BUILD_TYPE=Release
cmake --build build -j
cmake --install build --prefix "$HOME/.local"

The consumer project's CMakeLists.txt, whole: the package and the two targets a benchmark links:

cmake_minimum_required(VERSION 3.20)

project(speedgun-ngQuickStart CXX)

find_package(speedgun-ng REQUIRED)

add_executable(first_benchmark first_benchmark.cpp)
target_link_libraries(first_benchmark
                      PRIVATE speedgun-ng::speedgun-ng speedgun-ng::harness)

The first benchmark program, whole:

#include <cstdint>
#include <vector>

#include "speedgun-ng/barrier.hpp"  // sg::doNotOptimize is declared here
#include "speedgun-ng/benchmark.hpp"

auto bmSum(sg::State& state) -> void
{
  std::vector<std::uint64_t> cells(1 << 12, 1);
  std::uint64_t total = 0;
  for (auto _ : state) {
    for (const std::uint64_t cell : cells) {
      total += cell;
    }
    sg::doNotOptimize(total);
  }
}

SG_BENCHMARK(bmSum);

auto main(int argc, char** argv) -> int
{
  return sg::speedgunMain(argc, argv);
}

Configure, build, and run it:

cmake -S . -B build -DCMAKE_PREFIX_PATH="$HOME/.local"
cmake --build build
./build/first_benchmark

Its output on one host's run, with the numbers of that machine:

speedgun-ng 0.9.0 build=Release
bmSum                    iterations=   1066261  real time/iter (ns)=  657.575  cpu time/iter (ns)=  656.663  overhead floor (ns)=  684.000  endpoint samples=2

Run tools/ci/prepush.sh before you push: docs/pages/prepush.md carries the two tiers and the step map.

How you do it

The run loop

A benchmark is a function over State: the loop body runs once per iteration, and the harness settles how many iterations the run needs.

auto bmLoop(sg::State& state) -> void
{
  std::uint64_t total = 0;
  for (auto _ : state) {
    total += 1;
  }
  sg::doNotOptimize(total);
  sg::clobberMemory();
}

SG_BENCHMARK(bmLoop);

doNotOptimize keeps a value live across the barrier and clobberMemory pushes cached values back to memory; speedgun-ng/barrier.hpp declares both beside speedgun-ng/benchmark.hpp, the pair every snippet below includes.

Registration

SG_BENCHMARK registers a plain function, and its row carries the function name.

auto bmCells(sg::State& state) -> void
{
  for (auto _ : state) {
    sg::doNotOptimize(state.iterations());
  }
}

SG_BENCHMARK(bmCells);

SG_BENCHMARK_CAPTURE binds the arguments at registration, and the row names the capture label, bmAdd/pair.

auto bmAdd(sg::State& state, int left, int right) -> void
{
  for (auto _ : state) {
    sg::doNotOptimize(left + right);
  }
}

SG_BENCHMARK_CAPTURE(bmAdd, pair, 2, 3);

SG_BENCHMARK_TEMPLATE registers one instantiation, and the row names it, bmWidth<std::uint32_t>.

template<typename Type>
auto bmWidth(sg::State& state) -> void
{
  for (auto _ : state) {
    sg::doNotOptimize(state.iterations());
  }
}

SG_BENCHMARK_TEMPLATE(bmWidth, std::uint32_t);

Argument families and ranges

arg, args, range, ranges, denseRange, and argsProduct build the instance list, argName and argNames label the positions, and the body reads a position with state.range(i).

auto bmSquares(sg::State& state) -> void
{
  for (auto _ : state) {
    sg::doNotOptimize(state.range(0) * state.range(0));
  }
}

SG_BENCHMARK(bmSquares)
    .argNames({"cells"})
    .arg(32)
    .args({96})
    .argsProduct({{4, 8}})
    .rangeMultiplier(2)
    .range(64, 512)
    .ranges({{4096, 8192}})
    .denseRange(1024, 2048, 512);

argsProduct takes the product of the lists it carries, rangeMultiplier(k) settles the growth factor for the range and ranges calls that follow it on that family, and every instance prints as its own row, named by its labels. See argument families and argument access.

Fixtures

A Fixture subclass holds the state its methods measure, and setUp and tearDown run around the timed loop.

class TableFixture : public sg::Fixture
{
public:
  auto setUp(sg::State& state) -> void override
  {
    m_values.assign(3, 1);
    sg::doNotOptimize(&state);
  }

  auto tearDown(sg::State& state) -> void override
  {
    m_values.clear();
    sg::doNotOptimize(&state);
  }

protected:
  std::vector<std::uint64_t> m_values {1, 2, 3};
};

SG_BENCHMARK_F defines and registers in one step; SG_BENCHMARK_DEFINE_F only defines and SG_BENCHMARK_REGISTER_F registers it, printing TableFixture/bmTableRead and TableFixture/bmTableSize/1.

SG_BENCHMARK_F(TableFixture, bmTableRead)(sg::State& state)
{
  for (auto _ : state) {
    sg::doNotOptimize(m_values.front());
  }
}

SG_BENCHMARK_DEFINE_F(TableFixture, bmTableSize)(sg::State& state)
{
  for (auto _ : state) {
    sg::doNotOptimize(m_values.size());
  }
}

SG_BENCHMARK_REGISTER_F(TableFixture, bmTableSize).argsProduct({{1}});

Run control

minTime, warmupTime, iterations, and repetitions bound the measuring window and repeat it.

auto bmFixed(sg::State& state) -> void
{
  for (auto _ : state) {
    sg::doNotOptimize(state.iterations());
  }
}

SG_BENCHMARK(bmFixed)
    .minTime(200'000'000)  // 200 ms, in nanoseconds
    .warmupTime(50'000'000)
    .iterations(1000)
    .repetitions(5);

minTime and warmupTime take nanoseconds in the handle chain, while --min-time and --warmup-time take seconds on the command line, and each repetition prints a row with an aggregate row at the end of more than one.

Timing modes

CPU time is the primary time of a run by default, useRealTime makes real time the primary time, and useManualTime lets the body report each iteration's own time.

auto bmIo(sg::State& state) -> void
{
  for (auto _ : state) {
    sg::doNotOptimize(state.iterations());
  }
}

SG_BENCHMARK(bmIo).useRealTime().measureProcessCpuTime();

auto bmHand(sg::State& state) -> void
{
  for (auto _ : state) {
    state.setIterationTime(1500);
  }
}

SG_BENCHMARK(bmHand).useManualTime();

The primary time is the column the qualification test, the growth rule, and the aggregate statistics read: the CPU column by default, the real column under useRealTime, and the sum of the values the body reports through setIterationTime under useManualTime, which states that time in nanoseconds. measureProcessCpuTime leaves the primary time alone and selects the process CPU leaf for the CPU column. See two time columns, real time as the primary time, manual time, and the process CPU leaf.

Pause and resume

pauseTiming and resumeTiming take work out of the timed window, and ScopedPauseTiming is the guard that pairs them.

auto bmPaused(sg::State& state) -> void
{
  std::vector<std::uint64_t> scratch(64, 1);
  for (auto _ : state) {
    state.pauseTiming();
    scratch.assign(128, 2);
    state.resumeTiming();
    {
      const sg::ScopedPauseTiming guard {state};
      scratch.shrink_to_fit();
    }
    sg::doNotOptimize(scratch.front());
  }
}

SG_BENCHMARK(bmPaused).iterations(3);

A closed pause is subtracted from every time column of the row. The calls stand inside the loop, where the run's sampling window is open, one pause may stand open at a time, and each pause costs one more sample pair. The room for those samples follows the loop: the recorder reserves the pause room the family's previous attempt used, and a pair it cannot hold closes through a running fold that leaves the columns unchanged, with pause=folded beside the row. See pause and resume.

Hardware counter metrics

metricByName hands back a metric the host's table defines, so the reader names cpi rather than composing it.

#include <cstdio>
#include <string>
#include <string_view>

#include "speedgun-ng/counters_metrics.hpp"

auto describeMetric(std::string_view name) -> void
{
  const auto metric = sg::counters::metricByName(name);
  if (!metric.has_value()) {
    std::printf(
        "%s: %s\n", std::string(name).c_str(), metric.error().message.c_str());
    return;
  }
  std::printf("%s: group=%s unit=%s\n",
              std::string(name).c_str(),
              std::string(metric->group).c_str(),
              std::string(metric->unit).c_str());
}

--metric puts the same metric in a report column, one column per name, in the order the names are given; attaching a composed expression and folding a named metric against a window are at hardware counter metrics.

Multi-pass collection

A metric set wider than the host's published programmableCounters limit needs more than one measurement window, and metricMethod names how the run collects it: auto lets the harness choose, passes forces one replay per group of columns, multiplex keeps the single kernel-rotated plan.

#include <ranges>

#include "speedgun-ng/counters.hpp"

auto attachOverLimit(sg::BenchmarkHandle& handle) -> void
{
  using Leaf = sg::counters::Dim<0, 1>;
  const auto cpu = sg::counters::System::local().object("cpu");
  if (!cpu.has_value()) {
    return;
  }
  const auto limit = cpu->programmableCounters().value_or(0);
  for (const auto& entry : cpu->counters() | std::views::take(limit + 1)) {
    if (const auto leaf = cpu->counter<Leaf>(entry.name); leaf.has_value()) {
      handle.addMetric(sg::counters::Expression<Leaf> {*leaf}, entry.name);
    }
  }
}

Each pass times its own columns, every metric field carries a pass=<index> tag, and a passes line discloses the settled method=, the pass count= and the spread=; the split rule, the merge rule, the spread formula and the fallback for a host that publishes no limit are at multi-pass collection.

Skips

skipWithMessage ends a run early when the work cannot be done, and skipWithError ends it as a failure.

auto bmGuard(sg::State& state) -> void
{
  if (state.range(0) == 0) {
    state.skipWithMessage("no cells configured");
    return;
  }
  for (auto _ : state) {
    sg::doNotOptimize(state.range(0));
  }
}

SG_BENCHMARK(bmGuard).denseRange(0, 4, 4);

The report prints SKIPPED: <reason> for the first kind and FAILED: <reason> for the second, and DISABLED_ at the front of an instance name keeps it registered while the run, the --list output, and every --filter match skip it. See the DISABLED_ prefix.

The command line

One entry point, speedgunMain, reads the command line, and the options are long options alone.

auto bmRead(sg::State& state) -> void
{
  for (auto _ : state) {
    sg::doNotOptimize(state.iterations());
  }
}

SG_BENCHMARK(bmRead).argNames({"cells"}).arg(256);

--min-time and --warmup-time take seconds, and a usage error reports one line and exits with status 2. An option can also come from a file of one option per line named by --options, or from a SPEEDGUN_* environment variable named after the option, and --env=off takes the environment away from one run. The highest source that sets an option wins: the command line, then the option file, then the environment, then the built-in default. A run that took an option from a file or the environment, or that ran --interleave, prints one line after the version line naming each such option and the value that took effect. --threads=1,4 runs every family at one context and then at four, and --threads=2:16 takes the doubling counts from 2 to 16. --interleave runs the selected instances in a random order, and --interleave=7 fixes the seed that order uses. --help prints one line per option and stops, and --version prints the project version and stops; neither runs a benchmark.

Reading the report

A run prints a version line, then one row per instance and repetition.

auto bmFill(sg::State& state) -> void
{
  const auto cells = state.range(0);
  std::vector<std::uint64_t> row(static_cast<std::size_t>(cells), 0);
  for (auto _ : state) {
    row.front() = static_cast<std::uint64_t>(cells);
    sg::doNotOptimize(row);
  }
  state.setBytesProcessed(cells * 8);
  state.setLabel("filled");
}

SG_BENCHMARK(bmFill).argsProduct({{8}}).threadRange(1, 2);

The row carries bytes_per_second= from the byte setter and the label= field the label setter gave it, and Reading a report row shows the full run with the spread= statistic and the BIG_O and RMS pair of the fit. A row gives iterations=, real time/iter (ns)=, cpu time/iter (ns)=, overhead floor (ns)=, and endpoint samples=. The floor is the median cost of one sampling window for the run, so a fast loop prints a floor above its own per-iteration time, and the count is the sample pair taken at the window ends, plus one point for each chunk when the run reports percentiles. With repetitions, a final AGGREGATE row gives mean, median, sd=, cv=, min, max, and n=. A threaded result prints its merged row, bmFill/8/threads:2, then the disclosure of the contexts it merged: contexts=2 ctx0=SPIN/NO_PIN ctx1=SPIN/NO_PIN.

User counters

auto bmCount(sg::State& state) -> void
{
  const auto cells = static_cast<std::size_t>(state.range(0));
  std::uint64_t sink = 0;
  for (auto _ : state) {
    sink += cells;
    state.setCounter("cells", {static_cast<double>(cells)});
    sg::doNotOptimize(sink);
  }
}

SG_BENCHMARK(bmCount).argsProduct({{64}}).repetitions(3);

A counter is a named number the loop reports beside the times, and its flags say how the value scales. A run of bmCopyCells prints cells= and the bytes_per_second= rate beside the two time columns, and its AGGREGATE row carries one statistic line for each counter, so cells mean= and bytes_per_second mean= stand under the built-in ones. Names are capped at kMaxUserCounters, sixteen for one benchmark, and a name must be shorter than kMaxCounterNameBytes, so 31 characters; both bounds are SG_REQUIRE preconditions on State::setCounter, and a breach ends the run with the bound in its message. See user counters.

Throughput

auto bmScale(sg::State& state) -> void
{
  std::int64_t work = 0;
  for (auto _ : state) {
    work += static_cast<std::int64_t>(state.iterations());
    sg::doNotOptimize(work);
  }
  state.setItemsProcessed(work);
  state.setBytesProcessed(work * 4);
}

SG_BENCHMARK(bmScale).argsProduct({{1}}).repetitions(3);

setBytesProcessed and setItemsProcessed open the two rate counters the harness derives from the time it measured. The row gains items_per_second= and bytes_per_second= columns, each one the total the call passed divided by the primary time of the run, so a larger argument shows the throughput the loop held. Both calls take the total work of the whole run: a body that works a known amount per iteration passes that amount times state.iterations() after the loop, as the example does. See throughput.

Labels

A label is a trailing word a run prints after its numbers, so a row says which variant it measured.

  const auto cells = static_cast<std::size_t>(state.range(0));
  std::vector<std::uint64_t> block(cells, 3);
  for (auto _ : state) {
    std::uint64_t total = 0;
    for (const std::uint64_t cell : block) {
      total += cell;
    }
    sg::doNotOptimize(total);
  }
  state.setLabel("summed");
}

SG_BENCHMARK(bmScanBlocks).argNames({"cells"}).range(256, 4096).repetitions(3);

label=summed stands last on every row of the family, after the counters, and the AGGREGATE row carries the label the repetitions agreed on. See labels.

Custom statistics

A custom statistic turns the repetition times of one instance into one more named number on its aggregate row.

auto spreadOf(const std::vector<double>& times, double& spread) -> bool
{
  if (times.empty()) {
    return false;
  }
  double lo = times[0];
  double hi = times[0];
  for (const double value : times) {
    lo = value < lo ? value : lo;
    hi = value > hi ? value : hi;
  }
  if (lo <= 0.0) {
    return false;
  }
  spread = (hi - lo) / lo * 100.0;
  return true;
}

BenchmarkHandle::addStatistic("spread", sg::StatUnit::PERCENTAGE, &spreadOf) attaches the callback to the family. spread= 0.110 then prints beside the built-in statistics with the percentage unit the registration declared, and the names mean, median, sd, cv, min, max and n stay reserved: a callback registered under one of them breaches its precondition at the call. See custom statistics.

Aggregate-only reporting

reportAggregatesOnly keeps the repetition rows out of the report and leaves the aggregate.

auto bmCountWords(sg::State& state) -> void
{
  const std::string line =
      "speedgun-ng reports one row per repetition and one aggregate";
  for (auto _ : state) {
    std::size_t spaces = 0;

  }

SG_BENCHMARK(bmCountWords).repetitions(5).reportAggregatesOnly();

Complexity fit

A family fitted over its complexity sizes reports the curve each of its quantities follows.

auto bmSwapPasses(sg::State& state) -> void
{
  const auto cells = static_cast<std::size_t>(state.range(0));
  std::vector<std::uint64_t> values(cells, 1);
  for (auto _ : state) {
    for (std::size_t row = 0; row < cells; ++row) {
      for (std::size_t col = 0; col + 1 < cells; ++col) {
        std::swap(values[col], values[col + 1]);
      }
    }
    sg::doNotOptimize(values);
  }
}

SG_BENCHMARK(bmSwapPasses)
    .argsProduct({{8, 16, 32}})
    .complexity(sg::BigO::AUTOMATIC);

The family ends with a BIG_O row naming the curve and its coefficient, an RMS row with the fit error as a percentage, one pair for every quantity the family carries, and a SKIPPED row naming a quantity a member never set together with its reason. See complexity fit.

Execution contexts

A context is a thread the library runs, with an inbox of typed work and a policy fixing its wait mode and placement.

const auto kNoiseLoad = [](sg::WorkContext& work) noexcept
{
  while (!work.stopToken().stopRequested()) {
  }
};

auto main(int argc, char** argv) -> int
{
  const sg::ContextPolicy spin {.waitMode = sg::WaitMode::SPIN};
  sg::ExecutionContext load {spin};
  sg::WorkNode<decltype(kNoiseLoad)> node {kNoiseLoad};
  sg::dispatch(load, node);
  const int status = sg::speedgunMain(argc, argv);
  load.requestStop();
  load.drain();
  load.join();
  return status;
}

The bmQuiet row prints while the load spins on its own context; requestStop, drain, and join close the context after the run. See execution context lifecycle.

Threads

threads(4) runs one benchmark body on four contexts at once and prints one merged row for them.

auto bmSharded(sg::State& state) -> void
{
  const int index = state.threadIndex();
  for (auto _ : state) {
    sg::doNotOptimize(index + state.threads());
  }
}

SG_BENCHMARK(bmSharded).threads(4);

state.threadIndex() numbers the context running the loop, and state.threads() gives the count the instance asked for. See what a threaded row merges.

Topology placement

--placement picks one of five presets, none, core, l3, smt or compact, and the harness plans one cpu per context from the machine layout it reads once per process: core takes one thread per core, l3 one cpu per L3 group, smt the sibling threads of one core, and compact fills each L3 group before the next. A handle names its family's preset with placement, and the handle wins over the command line. Asking more contexts than the preset has places stops the batch with one line naming the preset and the counts. --topology prints the layout the plans come from. See topology placement in detail.

Regression gate

--compare=baseline,contender reads two report documents and answers whether the contender holds the rules you set; the comparison consults those documents and runs no benchmark of its own.

auto printComparison(const sg::ReportData& baseline,
                     const sg::ReportData& contender) -> int
{
  constexpr std::array kStateWords {
      "OK", "REGRESSED", "IMPROVED", "NOISY", "ADDED", "REMOVED", "SKIPPED"};
  const auto rule = sg::parseCompareRule("time@median:lower:5%");
  const auto answer = sg::compareReports(baseline, contender, {*rule}, {});
  if (!answer.has_value()) {
    std::printf("compare: %s\n", answer.error().c_str());
    return 2;
  }
  for (const sg::CompareEntry& entry : answer->entries) {
    const auto word = kStateWords[std::to_underlying(entry.state)];
    std::printf("%-12s %s\n", entry.name.c_str(), word);
  }
  std::printf("compare: the verdict is %s\n", answer->passed ? "pass" : "fail");
  return 0;
}

That pair answers one line per benchmark with its state word, OK, REGRESSED, IMPROVED, NOISY, ADDED, REMOVED or SKIPPED, and one verdict line compare: the verdict is fail; the command line answers a failed verdict with status 1 and a rejected rule or document with status 2. See regression gate.

A probe is a spinning context the harness pins to one free cpu of each L3 group the plans touch, and it counts the gaps the host inserts above a threshold while the batch runs. See jitter probe in detail for the option parts, the block field lines and the names.

Host noise pre-check

The pre-check measures the host noise on the planned cpus before the batch runs: it prints one block per measured cpu with the gap figures, the attribution deltas each naming its /proc source and the host settings, then one warning line per noisy planned cpu and the pinning-candidate line ranked by gap rate. strict refuses a run whose planned cpu stands noisy with status 2, and precheck=serial runs the pre-check windows one cpu at a time. See jitter probe in detail for the keys and the record.

auto bmMeasured(sg::State& state) -> void
{
  for (auto _ : state) {
    sg::doNotOptimize(state.iterations());
  }
}

SG_BENCHMARK(bmMeasured).threads(2).placement("compact");

auto main(int argc, char** argv) -> int
{
  sg::runJitterProbe({.thresholdNs = 1000000000,
                      .mode = sg::JitterProbeMode::PRECHECK,
                      .precheckSerial = true,
                      .tracerEngine = sg::TracerEngine::OSNOISE});
  return sg::speedgunMain(argc, argv);
}

Noise tracer

The --os-noise value runs the osnoise or the timerlat tracer across the pre-check window. The report prints one header line naming the engine and the tracer cpus, then one figure line per source per tracer cpu. The disclosure covers three host states: no tracefs mount at the standing path, no tracer engine, and no rights for the setup writes. It stands one line, tracer: not available, on the tracer lines alone, and the exit status stays 0. A cpus= list naming a planned cpu runs the tracer's own load beside the measured cpus. Hunter mode

--hunt puts a wide catalog event set on one benchmark and ranks the events by how far each one stands out of the run. --hunt=all selects every entry of every core device, and an address list, a glob such as uncore/* or a @file of addresses selects the rest. A hunt option beside no --hunt leaves the hunt off, and --hunt=none states the same run in words. A settled --hunt-emit-set beside no --hunt is the one exception: it names a file no hunt will write, so the run prints one line and ends with status 2. The hunt drives the multi-pass collection loop above, so it opens no second counter path.

// The ranked table of a hunt, with the refusals discovery handed back folded
// into the skipped list of the record. `rankEvents` decides the order, the
// noise mark and the size of the table (FR-014, FR-021, I-5).
auto rankHuntEvents(const std::vector<sg::hunt::EventSamples>& collected,
                    const std::vector<sg::hunt::SkippedEvent>& refused,
                    const sg::hunt::HuntOptions& options) -> sg::hunt::EntryHunt
{
  // No plan collected these scripted rows, so the record states no method.
  auto hunt = sg::hunt::rankEvents(collected, options, std::nullopt);
  hunt.skipped.insert(hunt.skipped.end(), refused.begin(), refused.end());
  return hunt;
}

The run prints its hunt on stdout behind a hunt: prefix. One plan line names the event count, the pass count and the settled method, one rank row gives the rate under the label of the norm beside the deviation, one skipped row gives the kind of a refusal, and one summary line counts the events that produced a usable sample. --hunt-budget takes one clause per bound: 120s and 8p bound the whole hunt in two stages, 0.5e bounds one event inside one stage, and 32g bounds the events of one multiplex group, and the plan line carries sample= and mux= beside budget= with one line under it for each budget that speaks. --hunt-emit-set=<file> writes the ranked addresses of the run, and --counter=@<file> reads such a file back as report columns. One line on stderr naming the value ends the run with status 2 for a value outside the range its option states, for a raw event code such as r4a03, and for a hunt beside --counter, --metric or --compare. A host that refuses every event prints the plan line, the skipped list and a summary that reads events=0/N, and the run ends with status 0. See Hunter mode for the selection forms, the options, the lines and the names.

Report views

One loaded report document renders four ways: the SVG histogram, the SVG plot, the static HTML page and the terminal text, all declared in speedgun-ng/views.hpp.

#include <cstdio>

#include "speedgun-ng/views.hpp"

// The document the run wrote at its json path loads back, and the
// text view prints the terminal figures of the primary time column.
auto printTimeView(const std::string& path) -> void
{
  const auto document = sg::loadReport(path);
  if (!document.has_value()) {
    std::printf("%s\n", document.error().c_str());
    return;
  }
  const auto text = sg::renderText(*document, "bmViews", "time", 4);
  std::printf("%s\n", text.has_value() ? text->c_str() : text.error().c_str());
}

The run writes its document at --json=path, loads it back with loadReport, and prints the five repetition rows and the aggregate row, then the text view: one line naming the column, one line per bin with its range, count and bar (100-200 ns: 2 first), and one line per recorded value (100 ns first).

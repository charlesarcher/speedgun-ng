enum class sg::CounterFlag: std::uint32_t
#include <speedgun-ng/benchmark.hpp>

The flag bits that turn a counter's stored value into the value its column prints (E-02, FR-002).

NONE prints the value the body set. RATE divides that value by the row's primary time in seconds. AVG_THREADS divides by the thread count of the run, one while threads stay out of scope. ITERATION_INVARIANT multiplies by the iteration count ahead of a rate division, and AVG_ITERATIONS divides by the iteration count. INVERT takes the reciprocal last, after every other flag (FR-003, FR-004, research D-02).

The bits combine through operator|, so a rate that averages over the threads of the run is CounterFlag::RATE | CounterFlag::AVG_THREADS, a rate over a per-iteration measure is CounterFlag::RATE | CounterFlag::ITERATION_INVARIANT, and the mean of a per-iteration measure is CounterFlag::AVG_ITERATIONS. A combined set is one value and the flags apply in the order above; the reference implementation spellings kAvgThreadsRate, kIsIterationInvariantRate and kAvgIterationsRate have no single-name counterpart here (FR-003, FR-004).

INVERT of a value that settled at zero keeps zero. The reference implementation prints an infinity at that point; a counter column that never prints an infinity is the contract, so the reciprocal is taken only where the value stands apart from zero (FR-005).

enum class sg::CounterBase: std::uint8_t
#include <speedgun-ng/benchmark.hpp>

The suffix a rendered counter value carries (FR-006).

K1000 renders with k and K1024 with Ki. The console report prints raw numbers, so the base never divides the value a column prints: a counter that holds 64 prints 64 under either base, and the base is the suffix a human-readable renderer would carry (FR-009, FR-010).

enum class sg::WaitMode: std::uint8_t
#include <speedgun-ng/execution_context.hpp>

How a context waits while its inbox stands empty (FR-004).

SPIN watches the inbox flag through the pause hint, YIELD yields to the scheduler, BLOCK waits in the standard atomic wait and dispatch() wakes it. No mode reads a clock or takes a timeout (FR-004, FR-039).

enum class sg::WorkNodeState: std::uint8_t
#include <speedgun-ng/execution_context.hpp>

The completion state of one work node (FR-009, FR-045, FR-049).

PENDING stands from construction until the loop takes the node, RUNNING stands while the loop runs the item, then DONE stands for an item that ran, or STOPPED for a node a dispatch() that observed the stop request refused and completed itself (FR-009, FR-050). The completing thread writes that state with release order as its last access to the node (FR-049).

#include <speedgun-ng/barrier.hpp>
template<class T>
void sg::doNotOptimize(T& value) noexcept

Keep value alive against the optimizer (FR-029, D-4).

The overloads and their constraints mirror DoNotOptimize of google/benchmark at the revision D-4 reads, commit e662de9aab8e705ecf4fa4bd41a207e5a0acfd0c, include/benchmark/utils.h. The const-reference overload that upstream marks deprecated stays out (D-4). Each statement names the value as an input and output operand and carries a memory clobber:

  • the lvalue and rvalue overloads outside the __GNUC__ branch take "+r,m" under __clang__ and "+m,r" elsewhere;
  • in the __GNUC__ branch, a type that is trivially copyable and no larger than a pointer takes "+m,r", and any other type takes "+m".

The constraint order is the alternative order the compiler prefers. Upstream puts memory first under gcc so a memory operand stays in memory, and the order is a property of the generated code that no runtime check can see.

The contract of a barrier is a property of the generated code, and no runtime check can see it, so this interface carries no runtime SG_ENSURE. The deviation from Principle II is recorded in the plan's Complexity Tracking, and test/barrier_shape.sh enforces the property at -O2 in CI.

#include <speedgun-ng/execution_context.hpp>
template<WorkItem Item>
void sg::dispatch(ExecutionContext& context, WorkNode<Item>& node)

Hand node to context and return without waiting (FR-010, FR-050).

The call links the node into that context's inbox, allocates nothing, and is legal from any thread and from work already running on that context (FR-003, FR-010, SC-04). dispatch() and requestStop() linearize at the enqueue: a dispatch that observes the not-stopped state appends the node and owns delivery, and a dispatch that observes the stopped state refuses the node and completes it STOPPED itself, so the loop never touches a node it never accepted (FR-050). Nodes one thread dispatches run in that order; work dispatched from inside a running item runs after that item ends, on the same context (FR-013).

Precondition

node stands in no inbox: its state is PENDING with no prior dispatch, DONE, or STOPPED (FR-009, FR-012)

Postcondition

none

SPEEDGUN_NG_EXPORT void sg::simulationStart() noexcept
#include <speedgun-ng/simulation.hpp>

Emits the marker sequence an attached tracer watches for, so collection begins at this point in the run.

The marker has three properties a caller needs before placing it. It has no architectural effect: it executes as a register move followed by a prefixed one-byte no-operation, and it leaves no state a program can observe after the call returns. A call is safe with no tracer attached. It occupies two instructions and perturbs a measurement it sits inside, so place it at the region boundary, outside the timed window (FR-019).

The tag's width matches the marker's immediate operand. A build targeting a processor family with no marker instruction compiles, links, and returns, emitting no marker; the tag stays published so a caller can still pass it to a tracer (FR-018).

Precondition

none

Postcondition

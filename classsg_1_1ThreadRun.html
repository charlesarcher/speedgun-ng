sg::ThreadRun class
#include <speedgun-ng/benchmark.hpp>

The harness-owned view of one threaded attempt and the contexts it runs on (FR-021, E-08).

Contents

  • Reference
    • Public functions

The harness builds the attempt, its body nodes and its two barrier rounds, and hands this view to the threadRunner callable of a family that attached one. The callable dispatches each body index onto the context of that index; the barriers, the per-context plans and the merge stay the harness's, so a runner the harness did not write cannot move a barrier wait inside a measured window (FR-019, FR-021).

Invariant

the context count stands at 1 or above, and every index of the half-open range from 0 to contextCount() names one body node of the attempt and the context that runs it, for the whole of the runner call (FR-021, FR-024)

void sg::ThreadRun::dispatch(int index)

Hand body index to the context of that index (FR-021).

The body node is the harness's: it opens that context's own thread-target plan, arrives at the start barrier, runs the timed loop, arrives at the stop barrier and folds that plan (FR-018, FR-019). The call returns without waiting, the way dispatch() of the context surface does (FR-010).

Precondition

index stands in the half-open range from 0 to contextCount() and no earlier call of this attempt dispatched that index, so an undispatched or twice-dispatched index ends the run with a violation at this point (FR-021, FR-024) and the two barrier rounds of the attempt hold every body of the run (FR-019, FR-021). No postcondition of this call can re-read that hand-off: the loop of the context takes the node as soon as it stands idle, so an inbox read here is not a stable observation (FR-010).

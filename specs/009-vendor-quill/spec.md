# Feature Specification: Vendor quill as a Private, Pinned Submodule

**Feature Branch**: `009-vendor-quill`

**Created**: 2026-09-30

**Status**: Draft

**Input**: User description: "We need a logger for speedgun (we had hwloc, yaml, gz, histogram,etc). Make sure to read how we import those libraries. The logger we will use is quill, here: https://github.com/odygrd/quill/releases/tag/v13.0.0. Let's get this imported as we have with the other libraries and make it available."

This feature delivers dependency infrastructure: quill enters the tree as a private, pinned, internal dependency of the speedgun-ng library, carrying the same characteristics the hwloc, simdjson, HdrHistogram_c, zlib, and yaml-cpp imports established (specs/003-vendor-hwloc, specs/004-vendor-simdjson, specs/005-vendor-hdrhistogram, specs/006-vendor-yaml-cpp). It defines no logging API and no call site built on top of quill.

## Clarifications

### Session 2026-09-30

- Q: What should prove that quill is a real, pinned dependency of the library, given that taking the address of a quill function cannot serve as that proof? (FR-008, SC-009) → A: A runnable test case that includes a quill example and prints a speedgun-ng counter through it. The archive symbol scan is dropped; the proof is a separate executable that links quill and the counter library and emits a real counter value.
- Q: How should warnings from quill's own headers be kept out of the project's strict warning set? (FR-010) → A: System include directory for the vendored headers, matching the mechanism the four existing brackets already use. Diagnostics originating in quill's headers are suppressed; the project's own translation units stay fully gated.
- Q: Should a developer be able to switch quill's own build options on when configuring speedgun-ng? → A: Pin every quill option to its default inside the ingestion bracket so a command-line flag cannot change them and no foreign option appears in the project's configuration. The owner confirmed alongside this answer that quill is an internal logger for now, which confirms Fixed decision 7 and changes no scope: no public logging interface ships with this feature.

## User Scenarios & Testing *(mandatory)*

### User Story 1 - The project builds with a pinned, vendored quill (Priority: P1)

A developer clones speedgun-ng with submodules and builds it. quill's headers compile inside the speedgun-ng library through one internal wrapper unit, and quill's own build configuration is consumed through the project's build. No path through the build selects a different quill, and replacing the pinned sources with a revision that declares a quill version other than 13.0.0 fails the build with a readable version diagnostic.

**Why this priority**: The vendored, pinned dependency is the foundation every other characteristic sits on. Without an ingested, version-locked quill there is nothing to hide, nothing to prove invisible, and nothing to re-pin. A logging library that is available but unpinned is worse than no logging library, because its behavior then varies with whoever last touched the submodule pointer.

**Independent Test**: Clone with submodules, build on Linux, build with the release preset, inspect `git submodule status`, grep the project's own build files for system-dependency queries, and swap the submodule tag to observe the version diagnostic fire. Every check runs against a build that satisfies this story alone.

**Acceptance Scenarios**:

1. **Given** a clean clone with submodules initialized, **When** a developer builds on Linux, **Then** the build succeeds, quill's headers compile from the submodule, and the speedgun-ng library consumes quill privately.
2. **Given** the same clone, **When** a developer builds with the platform's release preset, **Then** the build succeeds and reports no diagnostic promoted to an error from any quill header.
3. **Given** the same clone, **When** a developer builds on macOS, **Then** the build succeeds.
4. **Given** `git submodule status`, **When** inspected, **Then** the recorded commit is `eb802a37c7d585840324886a3d8648c9c2159952`, the commit named by tag `v13.0.0`.
5. **Given** the submodule checked out at any revision that declares a quill version other than 13.0.0, **When** the build runs, **Then** it fails with a readable diagnostic naming the expected quill version 13.0.0 and the version found.
6. **Given** a machine with a system quill installed, **When** the build runs, **Then** the build still consumes the submodule copy and never consults system package discovery.
7. **Given** a clone where `external/quill` is empty, **When** configuration runs, **Then** it aborts with a message naming the submodule init command, and it never falls back to a system copy.
8. **Given** the built speedgun-ng static archive, **When** audited, **Then** the archive carries quill's version tripwire and no quill symbol referenced solely to satisfy a proof, and the separate dependency check links, runs, and exits 0 with a speedgun-ng counter value present in its log output.

---

### User Story 2 - Consumers cannot observe quill (Priority: P1)

A downstream project installs speedgun-ng, configures a trivial consumer against it with `find_package(speedgun-ng)` on a machine with quill present, then builds and runs the consumer. Nothing a consumer can observe mentions quill: installed headers, package files, link interfaces, and exported symbols are all free of it, and the consumer build resolves zero quill.

**Why this priority**: Invisibility is the contract of this feature, the same contract the hwloc, simdjson, HdrHistogram_c, zlib, and yaml-cpp imports carry. Once quill leaks into an installed artifact, removing it later becomes a breaking change, and a hidden dependency in a published library is a maintenance trap for every downstream user. This matters more for a logging library than for the others: its bundled formatter sits in a namespace of its own precisely so it cannot collide with a consumer's own formatter, and that care is wasted if quill's headers are installed.

**Independent Test**: Install the library, audit the install tree, the package config files, and the shared-library symbol table, then build and run a consumer on a machine carrying quill and audit that the consumer build resolves zero quill. These checks run against any build that satisfies User Story 1.

**Acceptance Scenarios**:

1. **Given** an installed speedgun-ng, **When** the install prefix is audited, **Then** it contains zero files whose path names quill, headers, archives, shared objects, CMake package files, config files, and pkg-config files included.
2. **Given** the installed package files, **When** audited, **Then** `speedgun-ngConfig.cmake` and `speedgun-ngTargets.cmake` contain zero references to any quill target, path, or discovery call, and no link-interface entry of a shared speedgun-ng resolves to quill.
3. **Given** a shared-library build, **When** the dynamic symbol table is audited in CI, **Then** zero quill symbols are exported and the runtime dependency list of the installed shared library names no quill-owned object.
4. **Given** a machine with quill present, the vendored submodule in-tree and a system copy optional, **When** a trivial consumer is configured, built, and run against the installed tree, **Then** all three steps exit 0, and the consumer's configure log and link command resolve zero quill.

---

### User Story 3 - Re-pinning quill is documented and auditable (Priority: P3)

A maintainer updates the pinned quill by checking out a new tag, committing the submodule pointer, and bumping the version assertion. One short documentation section states exactly these steps, and the pinned commit recorded in the spec makes the pin auditable.

**Why this priority**: Re-pinning is a rare maintenance operation. Its value is keeping a future update cheap and its history traceable.

**Independent Test**: Follow the documentation section step by step on a scratch clone against a different release tag (newer or older) and confirm the build stays green; then bump the tag without bumping the version assertion and confirm the build fails.

**Acceptance Scenarios**:

1. **Given** the documentation section, **When** followed step by step, **Then** the pinned revision changes, the pointer commit lands, and the build stays green.
2. **Given** a submodule bump to any revision declaring a quill version other than 13.0.0, with the version assertion untouched, **When** the build runs, **Then** it fails with the version diagnostic.

### Edge Cases

- Clone without `--recurse-submodules` (an empty `external/quill` directory): configuration fails with a message naming the init command, with zero fallback to any system copy.
- A system quill present in any prefix: the build never selects it, verified by the FR-020 grep audit showing no discovery call naming it anywhere in the project's own build files.
- **quill ships no compiled artifact.** Its build defines an interface-only target and compiles nothing, so unlike the four compiled prior imports there is no vendored archive to merge into the speedgun-ng archive and no vendored object file to exclude from instrumentation. Every archive-level mechanism the compiled prior imports established has no quill counterpart, and the archive symbol scan those imports use has nothing to scan. FR-008 replaces it with a runnable check.
- **quill's headers define every symbol they declare.** Measured against the pinned tree, with debug information off so the figures compare code and not debug records: a unit that includes a quill header and takes the address of one quill function emits that function and its whole inline call graph as weak definitions in the same unit, and emits **zero** undefined symbols. An archive proof of the shape the compiled prior imports use, which requires an undefined reference resolved by another member, can therefore never pass here. The same measurement shows the cost. In the release configuration the referencing unit's object is 563,104 bytes carrying 194 quill symbols, against 3,744 bytes and 2 symbols for a unit that only reads quill's version constants, a factor of about 150. Unoptimized and without debug information the two are 2,670,304 and 24,648 bytes. A benchmarking library should not carry that weight for a symbol nothing calls, which is why FR-008 puts the proof in a separate executable. The shipped archive
carries no such proof.
- **quill's bundled formatter is namespaced to avoid collisions.** quill carries its own copy of a formatting library under a distinct namespace so a host with its own formatter sees no clash. The audit pattern in FR-020 matches the combined spelling, so the bundled copy cannot escape the leak audits through its separate namespace.
- **quill's build mutates global build state.** It force-sets a global build-type cache variable to an optimized value when none is set, and force-sets a master-project cache variable. Because the build-type mutation is global and not directory-scoped, a configuration that sets no build type would silently become an optimized build. FR-012 requires the project's own preset value to be asserted unchanged after quill's build configuration is consumed.
- **quill's option declarations predate a CMake policy the ingestion relies on.** Its declared minimum build-system version is below the version that introduced the policy governing whether an option declaration clears pre-set normal variables. Absent an explicit policy setting, its option declarations would clear the warning, sanitizer, and analyzer exemptions the ingestion sets in bracket scope, and the vendored tree would silently re-enter the project's gates. FR-013 requires the policy to be pinned explicitly.
- **consuming quill's build injects its whole option set into this project.** Its build declares roughly twenty-two options covering its tests, examples, documentation generation, named module, fuzzing, sanitizers, coverage, Valgrind, and install behavior. Nothing about consuming a dependency prevents a developer from passing one of them on this project's command line, and the consequential ones are exactly the switches FR-011 and FR-012 require off: a developer could pull quill's test suite, example programs, documentation generation, or sanitizers into this project's build without intending to. FR-013a pins all of them at their defaults using the same mechanism the yaml-cpp bracket already relies on, and keeps them out of the project's configuration entirely.
- **quill exposes its version as compiled constants. It publishes no preprocessor macro for them, and it does not publish its parsed version variable to the consuming scope.** A preprocessor-level version check is therefore impossible. Reading quill's own parsed version variable after ingestion fails for the same reason: that variable is set only in quill's own directory scope. FR-002 requires a compiled check against the constants, read through their public names.
- **quill's headers reach consumers with one warning relaxation attached.** Its interface target carries a single warning relaxation for Clang-family compilers. FR-009 requires the ingestion to confirm exactly that one option reaches the project's targets and no others, so a future upstream change cannot quietly widen it.
- **quill depends on the platform threading library.** Its build requires the platform threads package unconditionally and propagates that requirement to consumers. FR-016 requires the project's link-time dependency audit to account for it: on platforms where threads are part of the base C library the audit stays unchanged, and on platforms where they are a separate shared object the audit must still find zero quill-named entries.
- **quill's own build installs in two independent ways.** Its install rules and its example programs' install rules are gated by two different switches, so disabling one leaves the other live. FR-011 requires both switches off. The audit must prove that no quill package config, version file, pkg-config file, export set, or install-directory cache variable appears. Proving only that no install rule survived is a weaker claim and does not satisfy this requirement. A packaging configuration file in the build tree proves nothing on its own, because this project creates its own deliberately through its install rules; only the quill-named artifacts are evidence.
- **quill's build treats the vendored tree as an ordinary subproject with directory-scoped side effects.** Its build system is designed to be usable standalone and rewrites warning and instrumentation flag variables under several of its own switches. FR-012 and FR-013 require every such mutation to stay contained, verified by the analyzer, sanitizer, and coverage gates staying green.
- **the existing exclusion mechanism does not reach quill.** All four compiled prior imports clear warning, sanitizer, and analyzer variables inside their own build bracket, which works because each of those dependencies compiles targets inside its bracket. quill compiles nothing, so clearing variables there would affect no compilation at all, and the one translation unit that includes its headers is compiled in the project's own scope under the project's own strict flags. Left unaddressed, quill's headers would enter the warning gate, including a known false-positive overflow diagnostic from one supported compiler and real defects the project does not own. FR-010a supplies the mechanism that does reach them and FR-010b records why the bracket technique is absent here.
- Upstream offers two mutually exclusive switches that hard-stop the build with a preprocessor error when both are set (function-name reporting on, and detailed function-name reporting on), and one switch that requires a project-supplied definition in exactly one translation unit or produces a genuine one-definition-rule violation. FR-009 and FR-010 require none of these macros to be pre-set anywhere in the project tree, and the ingestion must leave all of quill's behavior-modifying switches at their defaults.
- Upstream's headers carry a real defect that surfaces under sanitizers in consumer code and in its own test build: a signed arithmetic overflow in its timestamp-counter calibration. FR-010 records that the vendored code stays out of instrumentation, which also keeps this finding out of the project's sanitizer gate; the risk is deferred to whichever future specification first emits log records, and named here so it is not rediscovered from scratch.
- Upstream's headers carry a real defect that surfaces under a strict-warning compiler in consumer code: a false-positive overflow diagnostic from one supported compiler family when a logging level is set. FR-002 requires the release-preset build to gate on this. Assuming upstream's own test-build failure is the
exposure leaves the consumer-side case ungated.
- Upstream's singletons carry default symbol visibility on GCC and Clang regardless of the host's visibility settings, and are reported to collide when quill's headers reach more than one shared object in a process. Neither applies here: this feature builds a single internal library into a single binary, where the linker merges one instance. The consequence was measured: a shared build of this project does export two quill symbols, `_ZN5quill3v136detail13get_thread_idEv` and `_ZN5quill3v136detail15get_thread_nameB5cxx11Ev`, both weak and stateless, because upstream marks them used and default-visible. FR-018 names them as the one permitted exception, FR-017 records the visibility rule that cannot be overridden from this project's side, and the exported-set audit fails on anything beyond those two.
- Upstream carries no companion submodule and no separate package requirement beyond the platform threading library; its bundled formatter travels inside the pinned tree, so the zero-external-runtime-dependency rule of the constitution is met without further vendoring.
- Windows: nothing in this feature blocks a later Windows build, but the Windows shared-library integration carries upstream-specific requirements that a static build does not. This feature drives no Windows-specific work beyond staying unprecluded.
- Licensing: the vendored tree carries its own permissive `LICENSE` file and it stays in-tree and ships with source distributions. The project's own license is permissive with no additional burden requirement, and the vendored license is permissive with attribution carried in-tree, so the two are compatible.

## Requirements *(mandatory)*

### Fixed decisions (settled by the brief and the five prior vendor imports)

1. **Submodule, pinned.** quill enters as a git submodule at tag `v13.0.0`, commit `eb802a37c7d585840324886a3d8648c9c2159952` (verified 2026-09-30 via `git ls-remote`: a lightweight tag naming the commit directly; it is the newest upstream release). No floating tag, no branches, no shallow tracking.
2. **Never resolve quill from elsewhere.** The only quill that exists for this project is the pinned one.
3. **Private consumption.** quill is consumed by the speedgun-ng library target alone, through a build-only private link edge.
4. **Invisible to users.** Every surface a downstream `find_package(speedgun-ng)` consumer can observe stays free of quill.
5. **Platform policy.** Linux is the enforced gate. macOS must keep building for developers. Windows stays possible by design with zero priority, runners, or funding.
6. **Vendored dependencies always on.** quill joins hwloc, simdjson, HdrHistogram_c, zlib, and yaml-cpp as an unconditional component of the speedgun-ng library on Linux and macOS. No preset, option, or build path may exclude any of the six.
7. **No logging API in this feature.** quill crosses zero public API boundaries here. It becomes reachable to the project's own internal translation units and to nothing else. The logging facility built on top of it, its configuration, its runtime startup, and its sink selection are a separate specification listing this one as prerequisite. This settles the brief's "make it available" as the same availability the other five dependencies have: present in the tree, usable internally, absent from every published surface.
8. **Inert until used.** No translation unit of the shipped library starts quill's backend, so the vendored dependency contributes no thread, no background activity, and no observable behavior to a build that does not log. This matters because quill's backend spins a polling thread and calibrates a hardware timestamp counter on first use, and a benchmarking library must not carry either by accident. The runnable dependency check of FR-008 is exempt: it is a test, it lives outside the shipped library and the exported target set, and emitting a record requires a running backend.

### Functional Requirements

Pinning and integrity:

- **FR-001**: The repository shall carry the quill sources as a git submodule at `external/quill`, outside `include/`, `source/`, and `test/`, recording submodule commit `eb802a37c7d585840324886a3d8648c9c2159952` (tag `v13.0.0`).
- **FR-002**: When the build runs with the submodule checked out at a revision that declares a quill version other than 13.0.0, it shall fail with a readable diagnostic naming the expected quill version 13.0.0 and the mismatch. The check consults no git metadata, so configuration from a source archive without git history stays supported. The check is compile-time. A configure-time check is unavailable here: the pinned tree publishes its version as compiled constants in a public header, publishes no preprocessor macro for it, and does not publish its parsed version variable to the consuming scope. The constants are read through their public names, which the versioned inline namespace also independently confirms.
- **FR-003**: The version check shall pin the full three-part version 13.0.0. A major-version-only check does not satisfy this requirement. This matches the exact-version posture the four prior imports carrying a compile-time tripwire established.
- **FR-004**: When the build starts with `external/quill` empty, the configuration shall abort with a message naming the submodule init command.
- **FR-005**: The build shall never consult a system quill: `find_package(quill)`, `pkg_check_modules(quill)`, and equivalent calls under any spelling of the FR-020 pattern, and all system fallback paths, are prohibited anywhere in the project's own build files.
- **FR-006**: The vendored license file (`LICENSE`) shall remain in-tree and ship with source distributions.
- **FR-007**: The documentation shall carry one re-pinning section for quill: check out the new tag, commit the submodule pointer, bump the version assertion.

Build integration:

- **FR-008**: The build shall consume quill through its own build configuration via `add_subdirectory` of the submodule with `EXCLUDE_FROM_ALL` and an out-of-tree binary directory, with the interface target linked into the speedgun-ng library through a build-only private edge; no public dependency edge shall exist. quill ships no compiled artifact, so no vendored archive is produced and no archive-merge step applies. The dependency shall be proven by a runnable check. Inspecting the shipped
archive yields nothing: a test executable shall link the speedgun-ng library and quill, drive a real speedgun-ng counter to a real value, emit that value through quill's logging entry point, and assert on what reached the log. The check runs as a test and is not part of the installed artifact or the exported target set. The shipped archive shall contain no quill symbol referenced solely to satisfy this check; the wrapper unit carries the version tripwire and nothing else.
- **FR-008a**: The runnable check shall exercise the two libraries together. quill alone does not satisfy it. Emitting a fixed string through quill would prove that quill links and would say nothing about whether the counter library interoperates with it. Interoperation is the property a future logging facility depends on. The check shall therefore obtain a counter value from the speedgun-ng counter interface, log it, and assert that the logged output carries the counter's value.
- **FR-009**: The ingestion shall confirm that exactly one compiler option reaches the project's targets through quill's interface target, the single warning relaxation quill attaches for Clang-family compilers, and that no other option and no compile definition propagates. Which switches sit at which value is FR-013a's subject, and this requirement does not restate it.
- **FR-010**: No macro upstream treats as mutually exclusive, or as requiring a project-supplied definition in exactly one translation unit, shall be pre-set anywhere in the project tree. The vendored code shall stay out of the project's warning, sanitizer, and coverage instrumentation, the identical policy all five prior imports record, with silent inconsistency between jobs treated as a defect. The vendored code sits outside the project's defect surface, and instrumented callers still get out-of-bounds detection on memory the vendored code allocates. Because the pinned tree reaches the project's targets through headers and not through
a separate archive, the exclusion is expressed at the include path. Excluding an archive from
instrumentation has nothing to act on, and every Linux job applies the policy identically.
- **FR-010a**: Per the Clarifications (2026-09-30), the ingestion shall mark quill's include directory as a system include directory, which is the mechanism all four compiled prior imports already use for their vendored library. Diagnostics originating in quill's headers shall be suppressed by that marking. Diagnostics originating in the project's own translation units shall remain fully gated, including the one that includes a quill header.
- **FR-010b**: The ingestion shall not rely on clearing warning, sanitizer, and analyzer variables inside its own build bracket to achieve FR-010 and FR-010a. That mechanism works for a dependency that compiles targets inside the bracket. quill compiles nothing, so there is no target in its bracket to clear anything for, and the one translation unit that includes its headers is compiled in the project's own scope under the project's own strict flags. Only the system include marking of FR-010a reaches the vendored headers. The plan records this as the reason no flag-clearing block applies to this dependency.
- **FR-011**: The ingestion shall switch off upstream's install switch and its example switch. Both are independent switches guarding two separate install paths, and both shall be off: the install path produces a pkg-config file, package config files, the full vendored header tree, an export set, a packaging-generator configuration, and four cache variables naming its install directories, and the example path installs example binaries through its own unguarded rules. Nothing from either path shall reach `CMAKE_INSTALL_PREFIX`, nothing shall be added to the exported speedgun-ng target set, and no packaging-generator configuration file shall appear anywhere in the build tree.
- **FR-012**: The ingestion shall contain every global and directory-scoped build-state mutation the vendored tree performs, so that the project's configured build type is unchanged after the vendored tree's build configuration is consumed, and so that the warning, sanitizer, coverage, and analyzer settings the ingestion relies on are not cleared by the vendored tree's own switch declarations.
- **FR-013**: Because upstream's declared minimum build-system version predates the policy that governs whether a switch declaration clears pre-set normal variables, the ingestion shall pin that policy explicitly to the new behavior before consuming the vendored tree. Absent the pin, upstream's switch declarations clear the ingestion's exemptions and the vendored tree silently re-enters the project's gates.
- **FR-013a**: Per the Clarifications (2026-09-30), the ingestion shall define every quill option at its upstream default inside its own build bracket before consuming the subtree, relying on the policy pin of FR-013 so that upstream's declarations cannot change those values. Two consequences are required. First, no command-line flag may alter this project's build through a quill option, including the install, example, test, documentation, and sanitizer switches that FR-011 and FR-012 require off. Second, the ingestion shall introduce no quill option into the project's configuration, so the project's own configuration surface stays free of foreign entries. A developer who passes one anyway leaves an entry that no code consumes and that changes nothing, because the build system records a command-line value before any ingestion runs and the pins make every later declaration inert. The entry is the developer's own, and removing it is their action. This specification places no requirement on it.
- **FR-014**: No header under `include/` shall include any quill header; quill's headers shall be includable only from `source/` translation units, and preferably through the one internal wrapper unit.
- **FR-015**: The build shall keep the submodule directory pristine: it configures and builds the vendored tree out of tree, and `git status` reports the submodule unmodified after a full build.
- **FR-015a**: The build shall carry no option, preset, or cache variable that excludes quill (or hwloc, simdjson, HdrHistogram_c, zlib, yaml-cpp) from the speedgun-ng library on Linux or macOS: all six are consumed unconditionally (Fixed decision 6).

Non-exposure (the privacy contract):

- **FR-016**: The output of `cmake --install` shall contain zero quill files: headers, archives, shared objects, CMake package files, config files, and pkg-config files. The platform threading library that upstream's build requires unconditionally and propagates to consumers shall be accounted for explicitly: the installed library's runtime dependency list shall name no quill-owned object, and any platform threading entry the merge introduces shall be recorded as a platform property and not as a leak.
- **FR-017**: The installed `speedgun-ngConfig.cmake` and `speedgun-ngTargets.cmake` shall contain zero references to any quill target, path, or discovery call; a shared speedgun-ng shall carry no link-interface entry resolving to quill. The vendored tree's singletons are deliberately exempt from symbol hiding, so a release gate that requires every symbol hidden shall treat them as a declared exception; the leak audits run against the installed shared object's exported symbols. Auditing the internal archive's contents instead would not satisfy this requirement.
- **FR-018**: On a shared-library build, the dynamic symbol table of the installed shared object shall export zero quill symbols, with exactly one exception: the two symbols `_ZN5quill3v136detail13get_thread_idEv` and `_ZN5quill3v136detail15get_thread_nameB5cxx11Ev` are permitted and nothing else is. Both are stateless inline helpers carrying no state and no singleton. The exception carries a written justification, which the constitution
requires. The pinned tree marks both `QUILL_ATTRIBUTE_USED`, which forces the compiler to emit them whether or not anything calls them, and `QUILL_EXPORT`, which on GCC and Clang resolves to default visibility regardless of this project's settings. They are reachable from any translation unit that includes `quill/Backend.h`, because that header includes `quill/backend/SignalHandler.h`, which includes `quill/backend/ThreadUtilities.h` unconditionally, and `Backend.h` is the only header publishing the version constants FR-002 needs. Removing them would require either editing the vendored tree, which FR-001 forbids, or a project-wide linker version script that changes export policy on every platform including the Windows gate that amendment 2.7.0 already suspends. The audit requires every exported quill symbol to appear in the allowlist, so a symbol outside it, a change of type, or any bundled-formatter symbol fails it. The audit deliberately does not require both allowlisted symbols to be present: a future upstream release that stops marking one of them used would export strictly less, which is the safe direction and must not read as a leak.
- **FR-019**: A downstream consumer test shall configure, build, and run a trivial consumer against the installed speedgun-ng on a machine with quill present, and the consumer build shall resolve zero quill through speedgun-ng; it is the authoritative proof of the privacy contract.
- **FR-020**: Every leak audit in this feature (FR-005, FR-016, FR-017, FR-018; SC-002 through SC-005, SC-009) shall search with the case-insensitive pattern `quill`, against file names, install-tree paths, package-config file contents, consumer configure and build logs, and symbol dumps. The pattern is deliberately the bare library name with no variant spellings, because upstream names its artifacts, its include directory, its namespace, and its bundled formatter namespace by that one spelling, and a real leak in any of them trips the check. The shared-build symbol audit shall require every exported symbol whose mangled name contains the five-character namespace encoding of quill's namespace to appear in the FR-018 allowlist, and shall fail on any exported symbol containing the encoding of its bundled formatter namespace, for which no exception exists. An empty-output requirement would contradict FR-018, which permits two exported quill symbols, and it would also fail a library that exports none. A search for the repository path spelling alone under other patterns does not satisfy these audits.

### Key Entities

- **Vendored quill submodule**: the quill sources carried in-tree; attributes: vendored path `external/quill`, upstream `https://github.com/odygrd/quill`, release tag `v13.0.0`, pinned commit `eb802a37c7d585840324886a3d8648c9c2159952`, license `LICENSE` (MIT), and the property that it ships no compiled artifact.
- **Imported interface target**: the build-system handle through which the speedgun-ng library consumes quill privately (upstream name `quill::quill`, an alias over an interface-only target). It carries no object files, so unlike the four compiled prior imports there is nothing to merge into the speedgun-ng archive.
- **Internal wrapper unit**: the one translation unit where quill's headers enter the build, carrying the version tripwire and the proof that quill's headers compile under the project's language level and warning gates. It carries no symbol reference to quill (FR-008).
- **Runnable dependency check**: the test executable that proves the dependency, outside the shipped archive. It links the speedgun-ng library and quill, drives a real counter, emits the counter's value through quill, and asserts on the log output.
- **Bundled formatter**: the formatting library quill carries inside its own tree under its own namespace, version 12.0.2; it travels with the pinned submodule, so it needs no separate vendoring, and its separate namespace means a host with its own formatter sees no collision.
- **Privacy contract**: the set of consumer-observable surfaces that must remain quill-free: installed headers, package config files, pkg-config files, target link interfaces, exported symbols, and include paths.

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: A clean clone with submodule init builds with every existing Linux CI job green, the same clone builds successfully under the platform's release preset with warnings promoted to errors, and the same clone builds successfully on macOS.
- **SC-002**: The install-tree audit finds 0 files whose path matches the FR-020 pattern under the install prefix.
- **SC-003**: The package-config audit finds 0 references matching the FR-020 pattern in the installed `speedgun-ng*.cmake` files.
- **SC-004**: The symbol audit finds every exported quill symbol in a shared build to be a member of the FR-018 allowlist, currently two entries, with a set of zero also passing; finds 0 exported symbols carrying the bundled formatter's namespace encoding; and finds the runtime dependency list of the installed shared library naming no quill-owned object.
- **SC-005**: The downstream consumer test on a machine with quill present: configure, build, and run all exit 0, and a grep of the consumer's configure log and link command with the FR-020 pattern finds zero quill resolutions.
- **SC-006**: Flipping the vendored submodule to any other release tag fails the build with one version diagnostic naming the expected version 13.0.0 and the version found.
- **SC-007**: After a full build, `git status` reports the vendored submodule directory unmodified, and the project's configured build type is byte-identical to the value the preset supplied.
- **SC-008**: The grep audit finds 0 occurrences of a `find_package(` or `pkg_check_modules(` call naming quill under any FR-020 spelling in the project's own build files, the vendored `external/` tree and the specification directories excluded.
- **SC-009**: The runnable check builds, links, runs, and exits 0, with a speedgun-ng counter value visible in the log output it produced. The shared-build audit of SC-004 stays at 0 exported quill symbols.
- **SC-009a**: The shipped speedgun-ng archive grows by less than 64 KB when quill is added, measured in the platform's release configuration, which is the configuration that ships and the one every gate uses. In that configuration the wrapper unit's object is 3,744 bytes, so the cap carries roughly seventeen times the measured cost. The measurement is a difference between two archives built from the same tree in the same configuration with and without the ingestion, and the runnable check's own object is excluded because it never enters the archive. The comparison is meaningless across configurations: the same unit is about 319 KB in a debug build, almost entirely debug information, which is why the cap names the release configuration because one number cannot cover every build.
- **SC-010**: The build tree contains no quill packaging configuration: no quill package config file, no quill package config version file, no quill pkg-config file, no quill export set, and none of the cache variables quill's install block defines. This project's own packaging configuration is created deliberately by its install rules and is out of scope. The configured project's targets carry exactly the one compiler option named in FR-009 and no compile definition originating in the vendored tree.
- **SC-011**: The release-preset build reports zero diagnostics originating in a vendored header, and the vendor's own version check firing is reproducible by flipping the submodule to a different tag.

## Assumptions

- **Vendored path**: `external/quill`, the root convention for every vendored dependency, and a single-word name, so the vendored path, the tools directory name, and the test names all read `quill` with no aliasing.
- **Source distribution**: this repository defines no packaging mechanism. FR-006's "ships with source distributions" means the vendored tree travels with the repository sources: a clone with submodules, or a snapshot of a populated working tree, carries `external/quill` with its `LICENSE`; no separate packaging step exists.
- **Wrapper unit path**: `source/quill/quill_gate.cpp`, following the one-wrapper-unit-per-dependency pattern (`source/yaml/yaml_gate.cpp`, `source/simdjson/simdjson_gate.cpp`); the plan records the final spelling.
- **No archive merge and no archive proof**: quill's build defines an interface-only target and compiles nothing, so no vendored archive exists to merge into the speedgun-ng archive and no vendored object exists to exclude from instrumentation. Every quill symbol a unit emits is defined inline in that same unit, so the cross-member reference proof the compiled prior imports route through has no quill counterpart and cannot be made to work. Per the Clarifications (2026-09-30), the proof is a runnable check outside the shipped archive. The plan records this as a named deviation and not an omission, and allocates a distinct test name for it so it is never confused with the `nm` proof the other five dependencies carry.
- **System headers in place of an excluded archive**: FR-010 and FR-010a's exclusion is expressed by marking quill's include directory as a system include directory, so diagnostics from its headers never reach the project's warning set while the project's own translation units stay gated. This is the mechanism the four compiled prior imports already use for their vendored library, promoted from the vendored target's own include property after the subdirectory is consumed. It produces the same observable outcome they achieve by excluding an archive, and it is the only mechanism that reaches a dependency which compiles nothing (FR-010b).
- **Sanitizer policy consistency**: the identical policy all five prior imports record, applied by every Linux job. One consequence is recorded here and left unsolved: the vendored headers carry a signed-overflow defect in their timestamp-counter calibration that a sanitizer build would report if the code were instrumented, so a future specification that emits log records must revisit this policy explicitly. This feature neither instruments the vendored code nor emits a log record, so the finding is out of scope here and named so it is inherited knowingly.
- **Strict-warning posture**: the release preset is the gate. The development preset is not one, because an unoptimized build cannot report a finding an optimizer's analysis produces. The vendored headers carry a false-positive overflow diagnostic from one supported compiler family when a logging level is set; the plan records whether a narrow warning relaxation is needed, and the release build proves the answer instead of
assuming it.
- **Threading dependency**: quill's build requires the platform threading package unconditionally and propagates it to consumers. No companion submodule and no further vendoring is required. The project's link-time dependency audit is the place this surfaces, and FR-016 states the required outcome.
- **System quill for the consumer premise**: quill publishes no system development package on the supported Linux distribution, so the downstream consumer job builds the pinned tree out of tree into a system prefix to establish the premise that a system copy exists, following the precedent the yaml-cpp import established. The premise is about the machine and says nothing about the build. The build still consumes the submodule.
- **Ingestion mechanism**: quill is a native CMake library with no sub-dependencies and no companion submodule, consumed through the established scope-isolated `add_subdirectory` bracket the simdjson, zlib, and yaml-cpp imports established, with its install switch, example switch, and every behavior-modifying switch at its default. No new build-system module is required, unlike the autotools module the hwloc import needed.
- **Install-rule suppression**: upstream's install path is guarded behind one switch and its example programs carry a second, independent, unguarded install path. FR-011 switches both off and audits the build tree for the quill-named artifacts that path would create, because "no install rule survived" and "no quill package configuration was generated" are different claims and only the second is what the consumer can observe. The check names quill's artifacts. Packaging configuration files in
general carry no signal, since this project generates its own, since this project generates its own.
- **Build-state containment**: upstream's build is written to be usable standalone and therefore mutates both directory-scoped and global build state. FR-012 and FR-013 require the ingestion to neutralize the global build-type mutation and to pin the switch-declaration policy, so the project's own presets and gates remain authoritative. The plan records the concrete mechanism.
- **Option pinning shares one mechanism with the policy pin**: defining upstream's options as bracket-scope variables and pinning the policy makes those declarations inert, which is the same lever the yaml-cpp bracket pulls for its install, shared-library, and test switches. Per the Clarifications (2026-09-30) the ingestion applies it to upstream's entire option set. A hand-picked few would need updating on every upstream release, so a future upstream option added after this pin defaults to off without touching the ingestion.
- **Version tripwire**: the pinned tree publishes its version as compiled constants and a versioned inline namespace, and publishes neither a preprocessor macro for it nor its parsed version variable to the consuming scope. A compile-time check against the public constant names is therefore the only mechanism that works, which is also the majority precedent among the prior imports. The namespace form gives a second, independent signal at no cost.
- **Symbol visibility**: upstream's export attribute resolves to default visibility on GCC and Clang regardless of the host's visibility settings, so its singletons cannot be hidden. Upstream reports those singletons colliding when its headers reach more than one shared object in a process; that report does not apply here, because this feature builds a single internal library into a single binary where the linker merges one instance. FR-017 records the visibility exception as declared and not as a leak, and the audits run against the installed shared object so the exemption never becomes a blind spot.
- **Constitution dependency clause**: quill enters as a build-time, privately consumed internal dependency. The installed speedgun-ng gains zero external runtime dependencies, satisfying the documented-justification requirement for dependencies with this record: the library needs structured logging internally for future diagnostic work, the pinned copy guarantees identical behavior on every user machine, and invisibility keeps the public dependency count at zero.
- **Pinned commit provenance**: `v13.0.0` verified 2026-09-30 via `git ls-remote` against `odygrd/quill`; it is a lightweight tag naming commit `eb802a37c7d585840324886a3d8648c9c2159952` directly, it is the newest release tag upstream, and the tree carries no submodules of its own. Upstream development past that tag stays untracked.
- **macOS verification**: developer-local. The CI matrix carries no macOS runner today; the macOS preset exists and must stay usable.
- **Scope boundaries**: excluded work: any public speedgun-ng API exposing loggers, sinks, patterns, or log records (quill crosses zero API boundaries here); backend startup, sink selection, log-level configuration, and every runtime logging decision (a separate specification listing this one as prerequisite); any call site that emits a log record (same separate specification); the choice between the vendored library and any other logging approach, which this brief settles; registry or download-based distribution of quill (vendoring or nothing); the capability policy for future vendored packages, decided inside those specifications; all Windows build work beyond staying unprecluded.
